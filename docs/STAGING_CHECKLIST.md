# Staging acceptance checklist

Candidate date: **25 November 2026**. Use a disposable copy and consistent pre-test backup. Never production. Keep the server console available: recovery containment intentionally denies all player login.

- [ ] Install the compiled addon on a Java 21 / Minecraft 1.21.1 dedicated NeoForge server with the exact reference JARs and Create dependencies. Confirm SQLite native loading and ledger ready on the staging Linux/CPU/filesystem. Verify a normal full-modpack client **without this addon** can join.
- [ ] Set a distinct staging serverInstanceId before first ledger creation. Verify non-OP cannot use audit commands; permission-level-two operator and console can. Test status, recent, player UUID history, inspect pages and unresolved.
- [ ] Through the actual Treasury Sell All button, sell loose + named/coloured vanilla shulker + offhand shulker stock. Check exact component matching, whole lots, unchanged price, exact removal/payment and preserved unrelated components. Save, stop and restart; inspect contents and both balances again.
- [ ] Repeat using real Sophisticated shulkers and standard stack upgrades (include omega/large counts). Reopen an already cached wrapper, place/break the box, stop/restart and check canonical persistence. Try same UUID aliases in one inventory and across two test players; never pay twice for one canonical removal.
- [ ] Verify nested containers/backpacks/linked/legacy/infinite/non-stack-upgraded boxes are skipped. Ordinary signs/enchanting tables remain sellable. Unsupported component payloads fail before mutations.
- [ ] While intent persistence is pending, move/replace the box, introduce a UUID alias, disconnect, change dimension, move out of range, or change shop price/template/mode/account. Confirm cancellation/no economic effects; no late callback may execute stale plans. Use a test-only delayed disk/worker environment, never modify production data.
- [ ] Exercise configured quantity/slot/byte limits, lot larger than limit, insufficient stock, payout int overflow and combined-balance overflow. Repeated clicks and multiple players must remain bounded, with one active request and no duplicate payment. Profile full boxes/component-heavy payloads and world-save contention; record MSPT and player-visible latency.
- [ ] In a disposable fault-injection copy, fail intent IO (no mutation), then fail outcome IO after mutation (persistent containment). Verify read-query/storage errors fail closed. Real disk-full/corrupt DB and exclusive ledger ownership should be exercised; keep original evidence.
- [ ] Kill the isolated server at PREPARED, after removal, after payment and before/after outcome acknowledgement. On restart verify dirty-boot recovery flags and login containment; compare recovered game files. **No automated refund/replay.** Complete the documented offline manual reconciliation on a test transaction.
- [ ] Verify normal stop/restart with completed transactions does not falsely clear existing recovery flags or reapply a sale. Replace one dependency with a same-version rebuild and confirm admission remains closed; restore the verified original.

Accept only after recording expected/actual item and currency totals, transaction IDs, environment versions, timings and unresolved findings. The supplied automated GameTest verifies Mixins, actual bank overflow, upgraded canonical edits/aliases/rollback/serialization and command permissions; it does not replace these full-client and crash-boundary tests.
